# 要求: エンディング演出のリッチ化

## 概要

ストーリーモードのクライマックスであるエンディング（`ALL_CLEAR` フェーズ）を、
視覚エフェクト・サウンド・物語の余韻の3軸で強化し、「救出完了」のご褒美感を高める。

## 背景

- 現状のエンディングは `ALL_CLEAR` で **5秒固定**（`constants.ts` の `ENDING_*`）。
  テキストと簡易ロケット（`renderer.ts` の `drawEnding` / `drawRocket`）のみで構成。
- 一方、プロジェクトには演出資産が揃っているが **エンディングでは未活用**:
  - `src/particles.ts` `ParticleSystem.spawnBurst`（取得・撃破スパークで実績あり）
  - `src/audio.ts` `AudioManager`（`SoundKey` にキーを追加すれば即拡張可能）
  - `src/background.ts` `Starfield`（視差スクロールの星空・星雲）
- ゲーム全体の到達点なのに演出が淡白で、達成感・物語の締まりが弱い。

## 実装対象の機能（What / ユーザー体験）

1. **視覚エフェクト強化**
   - 発進時に噴射炎・星屑のパーティクルを放射（`spawnBurst` を活用）。
   - 発進の瞬間に画面シェイク（新規）。
   - 発進中、背景の星を一時的に加速させ「ワープ感」を出す（`Starfield` に速度倍率）。
   - ロケット上昇に軌跡・グローを付与。
2. **サウンド演出**
   - 修理完了・発進・帰還ファンファーレなどを段階に同期して再生（`SoundKey` 追加）。
   - 各段階の遷移で1回ずつ鳴らし、重複再生しない。
3. **ストーリー / エピローグ**
   - 発進後に「帰還・感謝」の締めテキストを段階表示し、物語の余韻を持たせる。
   - 最後に `Press SPACE / Tap` で初期画面へ戻る導線（現状を踏襲）。
4. **尺**
   - 3要素を活かすため、現 5秒から拡張（目安 8〜10秒）。段階を増やす。
   - 正確な配分は設計フェーズで決定。

## 受け入れ条件（検証可能）

- [ ] エンディングが複数段階で進行し、各段階の遷移でパーティクル／サウンドが
      **1回ずつ**トリガーされる（同じ段階で重複再生しない）。
- [ ] 発進段階で噴射炎・星屑パーティクルと画面シェイクが発生する。
- [ ] 発進中、背景の星が一時的に加速（ワープ感）し、終了後は通常速度へ戻る。
- [ ] 発進後にエピローグテキストが段階表示され、最後に `Press SPACE / Tap` で
      初期画面（タイトル）へ戻れる。
- [ ] ミュート時は音が鳴らず、視覚演出は通常どおり進む。
- [ ] エンディング総尺の変更が `gameLoop` と `renderer` で**共有定数**を介して一致し、
      演出が途中で切れない（既存の定数共有方針 `ENDING_*` を踏襲）。
- [ ] エンディングに関する既存テスト（`tests/unit/gameflow.test.ts`）が
      新しい尺・段階に追随して緑になる。

## 成功指標

- 定性: クリア到達時の達成感・物語の締まりが向上する。
- 不具合ゼロ: 演出が途中で切れる／音が重複する不具合が発生しない。

## スコープ外

- スタッフロール / クレジット（今回は見送り）。
- 新規 BGM トラック（オシレータ生成音の範囲で対応、音源ファイルは追加しない）。
- スコア・実績の永続化、ゲームプレイ／難易度の変更。

## 未決事項（設計フェーズで判断）

- 各段階の正確な尺配分と段階数（カウントダウン演出を挟むか）。
- 画面シェイクの強度・減衰、星のワープ加速倍率。
- 追加 `SoundKey` の具体的な音色・周波数設計。
- 段階遷移トリガー（前フレーム比較 vs 段階インデックス管理）の実装方式。
