# 設計書

## アーキテクチャ概要

アイコン資産は「SVGがマスター、PNGはそこから手書きスクリプトで再現」という二本立て構成。
SVG（`icons/icon.svg`）が見た目の正、`scripts/generate-icons.js` が独自PNGエンコーダ（zlib + 手書きCRC/IHDR/IDAT）でSVGと同等の絵をラスタライズする。

```
icons/icon.svg  ──(視覚的に一致させる)──►  scripts/generate-icons.js
                                              │ node 実行
                                              ▼
                              icons/icon-192.png / icon-512.png / apple-touch-icon.png
```

両者は別実装なので、**同じ構図・座標・配色を二重に定義する**点に注意。512px基準の座標系で設計し、スクリプト側は `sc = size/512` でスケールする（既存方式を踏襲）。

## コンポーネント設計

### 1. icon.svg（マスターデザイン）

**責務**:
- 宇宙テーマのアイコン構図を宣言的に定義
- `manifest.json` から `sizes:"any"` の SVG アイコンとして直接参照される

**実装の要点**:
- 512x512 viewBox を維持
- 背景 `#05060F`、枠 `#2747C8`
- 自機=宇宙船（右向き三角形 + コックピット円 + 推進炎三角）
- 敵=エイリアン（上半円ドーム + 矩形ボディ + 波打つ底辺 + 白目+暗瞳 + 触角2本）
- 結晶ドット（菱形/円）= `#7DF0FF`、コア = `#FFE66D`

### 2. generate-icons.js（PNGラスタライザ）

**責務**:
- SVGと同一構図を手書きピクセル描画でPNG化
- 192 / 512 / 180 の3サイズを出力

**実装の要点**:
- 既存のプリミティブ（`fillRect`, `fillCircle`, `sp`）を再利用
- 新規に三角形/多角形塗りつぶし `fillPoly`（スキャンライン）を追加し、宇宙船・推進炎・エイリアン底辺の波打ちを表現
- アンチエイリアスは無し（既存同様、`image-rendering: pixelated` 前提）
- 色は16進ではなくRGB三組で渡す既存スタイルに合わせる
- 旧 `fillPacman` は宇宙テーマでは不要 → 削除（実装方針変更）

## データフロー

### アイコン更新フロー
```
1. icon.svg を宇宙テーマで書き換え
2. generate-icons.js を同じ構図に書き換え
3. node scripts/generate-icons.js を実行
4. 生成PNGを Read ツールで開いて目視確認
5. SVGと差異があればスクリプトを微調整して 3 へ戻る
```

## エラーハンドリング戦略

スクリプトはビルド時ツールであり実行時コードではない。座標がキャンバス外に出ても `sp()` が境界チェックで握りつぶす既存設計のため、描画自体は安全。
`node` 実行が失敗した場合はスタックトレースで原因を特定して修正する。

## テスト戦略

### ユニットテスト
- アイコン生成は視覚アセットのため自動ユニットテストの対象外（既存テストもアイコンを対象にしていない）
- 既存テストスイート（`npm test`）がアイコン変更によって退行しないことを確認

### 統合テスト
- `node scripts/generate-icons.js` が3ファイルを正常出力すること
- 生成PNG / SVG を目視確認し、宇宙テーマの構図になっていること
- `npm test` / `npm run typecheck` / `npm run build` がパスすること

## 依存ライブラリ

新規追加なし（既存の `zlib` / `fs` のみ使用）。

```
scripts/

```

## 実装の順序

1. icon.svg を宇宙テーマで書き換え
2. generate-icons.js に多角形塗りつぶしを追加し、構図を宇宙テーマへ書き換え
3. アイコン再生成と目視確認
4. 品質チェック（test / typecheck / build）

## セキュリティ考慮事項

- 外部URL・シークレットのハードコーディングは無し（純粋な描画ロジックと色定数のみ）
- 生成物はローカルの静的画像。外部送信なし

## パフォーマンス考慮事項

- ビルド時のみ実行される一回限りの処理。実行時パフォーマンスへの影響なし
- 生成PNGサイズは従来同等（フラットカラー中心で圧縮効率良好）

## 将来の拡張性

- 色を `src/constants.ts` と共有できれば二重定義を解消できるが、スクリプトがTSビルド成果に依存しない独立ツールである利点を優先し、今回は定数のローカル定義を維持する
