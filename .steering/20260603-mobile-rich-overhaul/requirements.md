# 要求内容

## 概要

PWA としてメイン用途であるスマホ（縦持ち）で全画面が映えるよう、ゲーム盤面を縦長レイアウトへ作り直し、操作キャラを宇宙飛行士に置換し、背景・壁・アイテム・UI のビジュアルをリッチに刷新する。

## 背景

「ステラー・ラン」は PWA としてスマホがメインの用途。しかし現状の盤面は `448 × 560px`（28列 × 35行、アスペクト比 4:5）で固定されており、縦長のスマホ画面（≒ 9:19.5）に対して縦に余りが出る。`fitToViewport`（`src/main.ts`）が縦横比を保ったまま横幅基準で拡大するため、**上下に大きな黒帯（隙間）** が生じ、画面を埋めきれていない。

加えて、描画はすべて単色図形（矩形・三角・円）によるレトロ路線で、操作キャラも宇宙船にとどまる。レトロなパックマンを踏襲する必要はなく、スマホで全画面が映える「リッチな宇宙ゲーム」へ引き上げたい。

## 実装対象の機能

### 1. 縦長盤面への再設計

- マップのグリッド比をスマホ縦長（≒ 9:19.5 寄り）にフィットするよう変更する。
- 3 ステージ（Stage 1 / 2 / 3）すべてを新しい縦長レイアウトで作り直す。
- 盤面比の変更に連動して、以下を再調整する：
  - 衝突判定（ピクセルベース判定の座標）
  - ゴースト AI（scatter ターゲット座標、ゴーストハウス出入り）
  - トンネル（ワープ列）の位置
  - ゴーストハウス・プレイヤー初期位置
  - 残機 / スコア UI の配置座標
  - ゲームバランス（速度・モードスケジュール等の必要な再調整）
- ユーザーは、スマホ縦持ちで盤面が画面の縦をほぼ埋めた状態でプレイできる。

### 2. PC（横長画面）での補完

- 盤面はスマホ最優先で縦長にフィットさせる。
- PC の横長画面で左右に出る余白は、動く星空背景で埋める。
- ユーザーは、PC でも左右余白が違和感なく埋まり、プレイに支障なく遊べる。

### 3. 操作キャラを宇宙飛行士へ置換

- 現在の宇宙船描画（`drawShipBody`）を、Canvas ベクター描画の宇宙飛行士に置き換える。
  - ヘルメット＋バイザー反射、スーツの陰影、進行方向に応じた向き・歩行/浮遊アニメーション。
- 残機アイコン・被弾 / 死亡演出も宇宙飛行士で一貫させる。
- 外部画像アセットを使わず、Canvas ベクター描画で完結させる（CSP / PWA を壊さない）。

### 4. 全体のビジュアルリッチ化

- 背景：深宇宙の動く星空・星雲・視差スクロール。
- 壁 / 通路：グラデーション＋ネオングロー＋角丸によるコロニー感。
- アイテム / エサ：エネルギー結晶・コアの発光強化、取得時のパーティクル / スパーク演出。
- UI / タイポグラフィ：スコア表示、READY / STAGE CLEAR / ALL CLEAR / GAME OVER のフォント装飾とトランジション。

## 受け入れ条件

### 縦長盤面への再設計

- [ ] スマホ実機 / エミュレータ（縦持ち）で、盤面が画面の縦をほぼ埋め、上下の黒帯が解消される（残余白は星空背景で充填）。
- [ ] Stage 1 / 2 / 3 すべてが縦長レイアウトで描画され、プレイ可能である。
- [ ] 各ステージに行き止まりや到達不能ドットが無く、全ドット取得でステージクリアできる。
- [ ] ゴーストの追跡（CHASE）・散開（SCATTER）・トンネルワープ・ゴーストハウス出入りが新マップで正常に動作する。
- [ ] 残機 / スコア UI が新グリッドに合わせて正しく配置・表示される。

### PC（横長画面）での補完

- [ ] PC の横長画面で左右に出る余白が星空背景で埋まり、プレイに支障がない。

### 操作キャラ（宇宙飛行士）

- [ ] 操作キャラが宇宙飛行士として描画される。
- [ ] 4 方向（上下左右）の進行で向き・アニメーションが切り替わる。
- [ ] 残機アイコン表示と被弾 / 死亡演出が宇宙飛行士で一貫している。

### ビジュアルリッチ化

- [ ] 背景に動く星空・星雲・視差スクロールが反映される。
- [ ] 壁 / 通路がグラデ＋ネオングロー＋角丸でリッチに描画される。
- [ ] アイテム / エサの発光が強化され、取得時にパーティクル / スパーク演出が出る。
- [ ] スコア・READY / CLEAR / GAME OVER のフォント装飾とトランジションが反映される。
- [ ] CSP（`img-src 'self' data:` 等）と PWA（manifest / service-worker）を壊さない。

### 全体品質

- [ ] 既存のユニットテスト / E2E スモークがグリーン（新グリッド前提への更新を含む）。

## 成功指標

- スマホ縦持ちで盤面が画面縦の大部分を占有し、上下黒帯が体感で解消される。
- レトロな単色描画から脱却し、背景・壁・キャラ・アイテム・UI が一貫した「リッチな宇宙ゲーム」の見た目になる。
- ローエンド端末でも極端なフレーム落ちなくプレイできる（視差・パーティクルの負荷が許容範囲）。

## スコープ外

以下はこのフェーズでは実装しません:

- 新ステージの追加（3 ステージ構成は維持し、レイアウトのみ刷新）。
- スコア / 難易度などゲームルールの新規追加（縦長化に伴う再調整は対象内）。
- 外部画像アセット（スプライトシート等）の導入（描画は Canvas ベクターで完結）。

## 未決事項

実装フェーズ（設計時）で判断・確認する:

- 縦長グリッドの具体的な行数・列数（目標アスペクトから設計フェーズで確定する）。
- 視差スクロール / パーティクルの負荷と、ローエンド端末でのパフォーマンス調整方針。
- 縦長化に伴うゲームバランス再調整の具体値（速度・ゴースト解放しきい値・モードスケジュール等）。
